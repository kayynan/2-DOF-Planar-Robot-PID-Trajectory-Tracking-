01 — Overview

What Are We Building?

A 2-DOF (2 Degrees of Freedom) planar RR robot is the simplest robot arm that can reach any point in a 2D plane. "RR" means two Revolute joints — joints that rotate. Think of your shoulder and elbow.

🦾

The Robot

Two rigid links connected by two rotary joints. Joint 1 at the base, Joint 2 at the elbow. The tip is called the end-effector.

📐

Kinematics

The math that maps between joint angles (θ₁, θ₂) and tip position (x, y). Forward and Inverse directions.

🎛️

PID Control

A feedback controller that computes how much to move each joint to minimize the error between desired and actual angle.

🎯

Trajectory Tracking

The full system goal: make the tip follow a predefined path (circle, figure-8, rectangle) smoothly and accurately.

💡

As an EEE control student, this project touches four core topics at once: rigid body mechanics, coordinate transforms, closed-loop feedback control, and discrete-time simulation — all in MATLAB.

02 — Robot Model

DH Parameters & Robot Geometry

The Denavit-Hartenberg (DH) convention is a systematic method to describe any robot's geometry using just 4 parameters per joint. For our planar robot:

Joint (i) θᵢ (Angle) dᵢ (Offset) aᵢ (Length) αᵢ (Twist) Meaning
1 θ₁ (variable) 0 L₁ = 0.5 m 0° Shoulder joint
2 θ₂ (variable) 0 L₂ = 0.5 m 0° Elbow joint

What each parameter means:

  • θᵢ — Joint angle (what the motor controls). This is our variable.
  • dᵢ — Link offset along Z-axis. Zero for planar robots.
  • aᵢ — Link length along X-axis. L₁ and L₂ here.
  • αᵢ — Link twist about X-axis. Zero for planar robots (all motion in XY plane).
📏

With d=0 and α=0° for both joints, this simplifies to a purely planar robot. The only things that matter are the two angles θ₁, θ₂ and the two lengths L₁, L₂ = 0.5 m each.

Workspace

The robot can reach any point within an annular ring:

// Reachability condition
|L₁ − L₂| ≤ √(x² + y²) ≤ L₁ + L₂

// For our robot (L₁=L₂=0.5):
0.0 m ≤ distance_from_origin ≤ 1.0 m

Any (x, y) target further than 1.0 m from the origin is unreachable. That's why we keep the trajectory center at (0.5, 0.3) with radius 0.2 — safely inside the workspace.

03 — Forward Kinematics

Forward Kinematics (FK)

Question: Given joint angles θ₁ and θ₂, where is the end-effector?

This is the easy direction — just basic trigonometry applied step by step along the kinematic chain.

Forward Kinematics
Angles → Position


Inverse Kinematics
Position → Angles (click/drag on canvas)

The FK Equations

We compute two intermediate points — the elbow and the tip — by summing up the contributions of each link:

// Elbow position (end of Link 1)
elbow_x = L₁ · cos(θ₁)
elbow_y = L₁ · sin(θ₁)

// End-effector position (end of Link 2)
x = L₁·cos(θ₁) + L₂·cos(θ₁ + θ₂)
y = L₁·sin(θ₁) + L₂·sin(θ₁ + θ₂)
🧠

Notice that Link 2's angle is (θ₁ + θ₂), not just θ₂. This is because θ₂ is measured relative to Link 1. The angle of Link 2 in world coordinates is their sum.

In MATLAB (from your code)

% Forward Kinematics — computed every time step x_act(k) = L1*cos(theta1_act(k)) + L2*cos(theta1_act(k) + theta2_act(k)); y_act(k) = L1*sin(theta1_act(k)) + L2*sin(theta1_act(k) + theta2_act(k));
04 — Inverse Kinematics

Inverse Kinematics (IK)

Question: Given a desired position (x, y), what angles θ₁ and θ₂ do the joints need?

This is the hard direction. It has multiple solutions, and sometimes no solution at all. We use the geometric method with the Law of Cosines.

Step 1 — Solve θ₂ (elbow angle)

Draw a triangle from the base to the elbow to the tip. The side lengths are L₁, L₂, and d = √(x²+y²). By the Law of Cosines:

d² = L₁² + L₂² − 2·L₁·L₂·cos(π − θ₂)
// Since cos(π−θ₂) = −cos(θ₂):
d² = L₁² + L₂² + 2·L₁·L₂·cos(θ₂)

// Rearrange for cos(θ₂):
cos(θ₂) = (x² + y² − L₁² − L₂²) / (2·L₁·L₂)

// Elbow-up solution (positive sin):
sin(θ₂) = +√(1 − cos²(θ₂))
θ₂ = atan2(sin(θ₂), cos(θ₂))

Step 2 — Solve θ₁ (shoulder angle)

k₁ = L₁ + L₂·cos(θ₂)
k₂ = L₂·sin(θ₂)

θ₁ = atan2(y, x) − atan2(k₂, k₁)
⚠️

Two solutions exist! Elbow-up uses +√(1−c²), elbow-down uses −√(1−c²). Your MATLAB code always picks elbow-up. In real robots, you choose based on avoiding obstacles.

In MATLAB (inlined in your code)

% Step 1: cos(theta2) from law of cosines c2 = (x_k^2 + y_k^2 - L1^2 - L2^2) / (2*L1*L2); c2 = max(-1, min(1, c2)); % clamp: prevent NaN from floating point % Elbow-up: positive square root for sin(theta2) s2 = sqrt(1 - c2^2); th2 = atan2(s2, c2); % Step 2: solve theta1 k1 = L1 + L2*c2; k2 = L2*s2; th1 = atan2(y_k, x_k) - atan2(k2, k1);
05 — PID Controller

PID Controller — Deep Dive

PID is a feedback control law. At every time step, it looks at the current error and computes a corrective output. We run one PID controller per joint.

P
Proportional

Output ∝ current error. Bigger error → bigger correction. Fast response but can overshoot.

I
Integral

Output ∝ accumulated error. Eliminates steady-state offset. Can cause windup if too large.

D
Derivative

Output ∝ rate of error change. Acts like a brake, damping oscillations. Sensitive to noise.

// Continuous-time PID:
u(t) = Kp·e(t) + Ki·∫e(τ)dτ + Kd·(de/dt)

// Discrete-time (Euler, what MATLAB uses):
error = θ_desired − θ_actual
integral += error · dt
derivative = (error − prev_error) / dt
u = Kp·error + Ki·integral + Kd·derivative

06 — Full System

The Complete Control Loop

Here's how all the pieces connect together every single time step (every 10 ms):

1

Trajectory Generator

Outputs desired tip position (xd, yd) at time t. Circle: xd = cx + r·cos(ωt)

↓
2

Inverse Kinematics

Converts (xd, yd) → desired joint angles (θ₁_des, θ₂_des) using law of cosines

↓
3

PID Controller — Joint 1 & Joint 2

error = θ_desired − θ_actual → compute u = Kp·e + Ki·∫e + Kd·ė

↓
4

Joint Dynamics (Plant)

θ_actual(k) = θ_actual(k−1) + u·dt². Simplified 2nd-order integrator model.

↓
5

Forward Kinematics (Feedback)

Converts actual (θ₁, θ₂) → actual tip position (x_act, y_act) for plotting

↺ repeat every dt = 0.01 s
🔄

This is a joint-space PID controller. The IK runs offline (pre-computed before simulation). The PID only sees joint angles, not (x,y) directly. An alternative is task-space control where the PID operates on x,y errors directly using the Jacobian — more complex but more flexible.

07 — MATLAB Code Walkthrough

Your MATLAB Code — Line by Line

Section 1: Trajectories

All 3 shapes are just parametric equations. omega = 2π/T ensures one full loop per simulation.

% Circle: standard parametric form xd_circle = cx + r * cos(omega * time); % x oscillates yd_circle = cy + r * sin(omega * time); % y oscillates 90° offset % Figure-8: y runs at DOUBLE frequency xd_inf = cx + r * sin(omega * time); yd_inf = cy + (r/2) * sin(2*omega * time); % 2× = figure-8

Section 2: PID Loop Structure

The core PID loop runs for each joint independently at every time step k:

for k = 2:N % === JOINT 1 === e1 = theta1_des(k) - theta1_act(k-1); % current error e1_int = e1_int + e1*dt; % integral (sum of past errors) e1_dot = (e1 - e1_prev)/dt; % derivative (rate of change) u1 = Kp1*e1 + Ki1*e1_int + Kd1*e1_dot; % PID output e1_prev = e1; % save for next derivative % === PLANT: simplified joint dynamics === theta1_act(k) = theta1_act(k-1) + u1*dt^2; % integrate acceleration % === FORWARD KINEMATICS: get actual tip position === x_act(k) = L1*cos(theta1_act(k)) + L2*cos(theta1_act(k)+theta2_act(k)); end

Why u * dt²?

The simplified plant model assumes unit inertia: the control signal u is treated as angular acceleration. Integrating twice:

θ̈ = u → θ(k) = θ(k-1) + θ̇·dt → θ(k) ≈ θ(k-1) + u·dt²

// In a real robot: J·θ̈ + B·θ̇ = τ (torque) // Here we simplify to: θ̈ = u (J=1, B=0)
  • Q

    Why two separate PID controllers?

    Each joint is an independent actuator. In a decoupled model (which we use here), we treat them separately. A more advanced approach would account for coupling torques using the full dynamic model (Lagrangian/Newton-Euler).

  • Q

    Why pre-compute IK before the loop?

    Because our trajectory is deterministic (known ahead of time). In a real robot reacting to unknown environments, IK would need to run in real-time every loop.

  • Q

    What does RMS error mean?

    Root Mean Square error = √(mean of squared errors). It's the standard measure of tracking accuracy. Lower is better. Typical values in our sim: <5 mm.
